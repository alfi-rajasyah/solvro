# Frontend conventions (React + Vite + Tailwind v4 + TanStack Query)

- **Imports**: `@/` alias = `src/` — no deep relative imports.
- **API**: everything goes through `apiRequest<T>` in `src/lib/api.ts` (bearer from `localStorage["solvro.token"]`, base `/api`) — never call `fetch` directly from a component or hook.
- **Server state**: all hooks in `src/lib/queries.ts`; keys in `queryKeys`, admin hooks in the separate `adminQueryKeys`, pipeline hooks in `pipelineKeys` (whose `root` is the deliberate invalidate-everything prefix; `list` is its own key — mutations invalidate exactly what they touch, never by prefix accident) — don't mix namespaces. Inline-edit mutations use the optimistic pattern: `onMutate` cancel + snapshot + optimistic write, `onError` rollback, `onSettled` invalidate.
- **Auth & theme**: `AuthProvider`/`useAuth` in `src/lib/auth.tsx`; route guards are components (`src/components/*Guard.tsx` — auth, admin, executive, pipeline, and the generic permission-gated `PermissionGuard`). Theme only via `src/lib/theme.tsx` — never poke `documentElement.classList` directly.
- **Tailwind v4 is CSS-first**: there is no `tailwind.config.ts`/`postcss.config.js`. The theme lives in `src/index.css`'s two `@theme inline` blocks (Solvro tokens + shadcn semantic bridge). Both MUST stay `inline` — a non-inline `@theme` freezes `var(--token)` resolution at `:root` and breaks the subtree `dark` pins on Login/Sidebar. Dark mode is the `@custom-variant dark` in `index.css`. New colors/sizes go in the primary `@theme inline` block — never arbitrary hex in components.
- **Headless stack is Base-UI**: `src/components/ui/` primitives are `@base-ui/react`-backed — never reintroduce `radix-ui`.
- **Vendored code** (`ui/`, `reui/`): re-running the shadcn/ReUI CLI strips local edits — mark every hand-touched site `// SOLVRO PATCH` so re-pulls don't silently clobber. Some shadcn-registry items (e.g. `separator`) resolve their canonical `ui.shadcn.com` version through a `radix-ui` dependency and the CLI prompts interactively to install it — decline and hand-author on `@base-ui/react` instead (see `ui/separator.tsx`).
- **Popover z-index**: overrides go on the Positioner via `PopoverContent`'s `positionerClassName` — Base-UI's Positioner carries an inline transform that creates its own stacking context, so Popup-level z-index does nothing. Convention: `z-101`, exactly one above `Modal.tsx`'s `z-100` — if the modal layer ever moves, move the pickers with it.
- **Dates**: `DateField`/`DateRangeField` speak plain calendar days (`"yyyy-MM-dd"`), never ISO instants — an ISO contract caused an off-by-one-day picker walk-back east of UTC. Convert only at call-site boundaries via `src/lib/dateField.ts`; persisted `Task.startDate`/`dueDate` remain ISO instants.
- **Display dates and words**: show dates only through `src/lib/formatDate.ts` (day-first, 24-hour, host-locale-independent) — never `toLocaleDateString`, `Intl.DateTimeFormat` or per-screen month lists. Domain enum display text (statuses, priorities, risk, weekly) comes from `src/lib/labels.ts` — never hand-write "To do"/"In progress" etc. in a component. Type sizes use the named roles in `index.css` (`text-meta` for 12px chips/secondary text) — no arbitrary sub-12px `text-[Npx]`.
- **Mobile**: usable down to 375px; desktop-only chrome behind `md:` (768px) — never a separate mobile component tree. Modals go edge-to-edge on phone via `Modal.tsx`; the Gantt is desktop-only with `ProjectList` as the phone fallback.
- **Icons**: app chrome uses the `material-symbols-outlined` font; `lucide-react` appears only inside vendored `ui/`/`reui/` files (ignore `components.json`'s `iconLibrary: "lucide"` for app code). `src/index.css` imports the icon font's stylesheet into a cascade layer (a production build hoists that `@import` to the top, so the layer ends up lowest) and restates the `.material-symbols-outlined` rules in `@layer base`, where the class beats preflight's `button { font: inherit }`. Size and display utilities on the icon element apply; an icon with no size class renders at 24px. Check an icon change in a production build (`vite build` + `vite preview`), not only the dev server, which does not hoist.
- **Navigation**: Sidebar and the ⌘K palette both render from the single `NAV_COMMANDS` catalogue in `src/lib/navCommands.ts`; top-bar titles/breadcrumbs come from `src/lib/routeMeta.ts`. A new project sub-view registers in `App.tsx` (route), `ProjectDetail.tsx` (tab list) and `PROJECT_VIEWS` in `routeMeta.ts` (an unlisted view reads as "Not found" in the title; `routeMeta.test.ts` fails if they drift).
- **antislop filter (mode: during)**: for any change to UI or user-facing copy, read `docs/DESIGN.md` for direction, then `docs/reference/antislop.md` as the filter, and write down one line of reason per visual or copy decision. Scoping for this repo: the mode and the install are settled (skip the file's wizard and its "during or after" question); the dial is the one in `docs/DESIGN.md`'s frontmatter; where `DESIGN.md` prescribes a pattern antislop names (uppercase `text-label-caps`, pill status chips, the dark default, mono ID tags), `DESIGN.md` wins; its marketing-page rules (hero, pricing, testimonials, FAQ) do not apply to an internal tool; the em dash ban covers strings a user reads, not comments, docs or the changelog; its 44px touch target applies to touch input only, desktop density stays; a missing asset or missing copy is an honest placeholder reported upward, never an invented final. Audits are written to `docs/plans/antislop-audit-NNN-YYYY-MM-DD.md`, never an `anti-slop/` folder.
- **Shared UI primitives from the 2026-11-10 audit** (`docs/archive/plans/antislop-audit-001-2026-11-10.md`): a missing value renders `EMPTY_VALUE` from `src/lib/emptyValue.ts` (an en dash), never a typed dash; an icon element is `aria-hidden="true"`, or carries an `aria-label` when it is itself the control, never both; a control under 44px that a phone user taps takes the `tap-target` utility (touch input only; never on an `absolute`/`fixed` element or one using `after:`); text on a solid `bg-primary` is `text-on-primary`; pointer and not-allowed cursors come from the base layer in `index.css`, so a clickable non-button (a card `div`) still needs its own `cursor-pointer`. `gates.sh` guards the dash, icon and on-primary rules.
- **Page toolbars**: the counts-and-actions row above a list, board or table uses `TOOLBAR_BUTTON_PRIMARY` / `TOOLBAR_BUTTON_OUTLINE` / `TOOLBAR_STAT` / `TOOLBAR_BOX` from `src/lib/utils.ts` (one 32px box, matching the Gantt toolbar) — never a hand-copied button class, a row chip or a filled colour block. One solid primary action per toolbar at most.
- **Changing how an existing screen looks**: fix the defect, keep the look. A restyle or relayout of an existing screen is described to the user (before and after) and approved before it is built, including when a filter or audit finding suggests it; decorative findings on existing screens default to "keep".
- **Pages are lazy**: routes in `App.tsx` load through `lazyPage` (`src/lib/lazyPage.ts`), behind the Suspense boundaries in `Shell.tsx` and `ProjectDetail.tsx`; a new heavy page should be lazy too. `npm run check:bundle-size` guards the 1 MB entry-chunk budget.
